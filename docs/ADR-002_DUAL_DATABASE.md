# ADR-002 — PostgreSQL and MongoDB Data Ownership

- Status: Accepted for M2 foundation
- Date: 2026-08-27

## Decision

ECHO PROTOCOL uses PostgreSQL as the authoritative relational/transactional store and MongoDB
as the raw telemetry event store.

PostgreSQL owns users, sessions, profiles, wallet/economy, shop/inventory, payment records,
match result summaries, rewards, and aggregated Player/Team AI profiles. MongoDB owns raw
gameplay telemetry and detailed AI behavior/context events.

## Consistency rules

- A UUID generated by the authoritative host/backend is reused as `matchId` across stores.
- MongoDB canonical telemetry `id` (`_id`) is the idempotency key for retries.
- There are no foreign keys or joins across databases.
- Wallet, reward, inventory, payment, and match-result transactions never depend on a MongoDB
  write succeeding in the same transaction.
- Telemetry aggregation may write derived profiles to PostgreSQL asynchronously in a later task;
  raw MongoDB documents never directly mutate economy state.
- MongoDB failure makes telemetry ingestion unavailable and database readiness unhealthy, but it
  does not prevent the API process or PostgreSQL-backed Auth endpoints from running.

## M2 scope

M2 includes local MongoDB orchestration, configuration, health checking, indexes, the versioned
event contract, and authenticated batch ingestion. Aggregation/AED and retention policies remain
M4 work after telemetry samples stabilize.
